# 技能库开源前的泄露体检（publishing preflight）

> 回答「我这些技能能上传 GitHub 吗」时走这条。它与 `skill-security` 互补：
> `skill-security` 审「装进来的技能安全吗」，这里审「**我自己的库传出去有没有泄露**」。

## 铁律

1. **先扫描再回答，不靠印象。** 「应该没有敏感信息」是本任务最常见的错答。
2. **先分类再扫描**：整个 `skills/` 根目录里混着三类东西，只有第一类能考虑上传。
3. **凭据 ≠ 全部风险。** 内网 IP / 手机号 / 平台 ID 的泄露面比 API key 更大 —— 拿到 `192.168.99.X` + 蒲公英固定地址就等于交出家庭网络拓扑。
4. **不自动脱敏**。扫完报数、给出选项，让用户决定：脱敏 / 私有库 / 不传。改 100+ 个文件是破坏性操作。
5. **已有 `.git` 的子目录要先查 remote** —— 里面可能是 clone 的第三方仓库，推上去等于冒充原创。
6. **先确认 gh 登录的那个账户是不是用户的**，再建库。`gh` 能用只证明凭据存在，**不证明归属**。
   取实际登录名用 `gh api user --jq '{login,name,email,created_at}'`，**别拿配置里的提交署名去猜**
   （实测两者不同，用猜的那个建库直接 404），再请用户在浏览器确认一次。
   **归属没确认前不要建 PUBLIC 库** —— 推上去就是任何人可搜索访问的。
   改可见性随时可做且不动内容：`gh repo edit <owner>/<repo> --visibility private`。

## 三类目录

| 类别 | 典型 | 处置 |
|---|---|---|
| **可考虑上传** | `SKILL.md` + `references/` + `scripts/` 构成的技能目录 | 扫 → 脱敏 → 上传 |
| **必须排除** | `.archive/`（归档的旧技能）、`.curator_backups/`、`skills.tar.gz`、`.usage.json`、任何 `*.bak.*` | 加 `.gitignore`，**绝不上传** |
| **机器运行态** | 索引缓存、扫描缓存、快照清单、审计日志 | 加 `.gitignore`，**绝不上传** |
| **第三方仓库** | 子目录带 `.git` 且 remote 指向他人 | 排除，或只取内容重新 init |

`.archive/` 和 `.curator_backups/` 是泄露重灾区：备份里的 `cron-jobs.json` 直接含用户平台 ID。

### 「机器运行态」这一类比归档更容易漏

归档目录有名字（`.archive`）一看就知道要排；**机器运行态没有**——它们就散在根目录，
名字像正常文件，提交时顺手就带走了。实测一次全库扫描（84 个 SKILL.md / 1300+ 文件）里，
`git add -A` 后仍被抓到的 PII 来源全在这一类：

| 路径 | 体积/形态 | 泄什么 |
|---|---|---|
| `.hub/` | 47 MB（`index-cache` 单文件就 48 MB） | 联系人手机号（3 个）、扫���缓存哈希、audit.log、lock.json |
| `.curator_state` / `.curator_suppressed` | 单个 JSON | 本机绝对路径、上次运行时间 |
| `.bundled_manifest` / `.snapshot_now_*.json` | 快照清单 | 本机路径 + 联系人手机号 |

**判据：任何「每次跑都会变」的文件都不该进版本库。** 它们不是资产，是日志。
判别方法：`git status` 里这类文件会在每次提交时冒出来淹没真 diff——看见就先问「它变是因为人改了它吗」。

### 排除项要写进 `.gitignore`，不是靠记性

`skills/` 一旦 `git init`，排除清单就是唯一闸门。**每条排除项必须在 `.gitignore` 里写一行注释说明为什么排**，
否则半年后没人敢删那条规则。典型骨架：

```gitignore
# 机器运行态：每次跑都变，进版本库会淹没真实 diff
.hub/
.curator_state
.curator_suppressed
# 快照/清单：含本机路径与联系人
.bundled_manifest
.snapshot_now_*.json
# 归档与备份：已合并/退役的技能；备份 tar 里的 cron 配置含平台 ID
.archive/
.curator_backups/
```

**首次提交前必须逐项验闸门真的关上了**，别只写完就提交：

```bash
git add -A && git status --short | awk '{print $2}' > /tmp/to_commit.txt
wc -l < /tmp/to_commit.txt                      # 提交规模
grep -cE '^\.archive/|^\.curator|^\.hub/' /tmp/to_commit.txt   # 每个排除项各查一次，必须 0
```

注意 `grep -E` 匹配 `.archive` 时会命中**文件名里含 archive 字样的正常技能**
（如 `references/archive-hygiene-two-zones.md`）——那是误报，看一眼再下结论，别当成闸门失效。

## 扫描脚本

```bash
python3 ~/.hermes/skills/knowledge-management/skill-library-curation/scripts/publish_preflight.py \
    --root ~/.hermes/skills
```

只输出统计与文件清单，**不修改任何文件**。分类：

- `CRED_HIGH` — 真实 API key / token / 私钥（`sk-*` / `ghp_*` / `AKIA*` / `BEGIN PRIVATE KEY`），排除明显的 `sk-abc...2345` 这类测试占位
- `PII` — 手机号、平台 ID（QQ / Telegram）
- `TOPOLOGY` — 私网 IP（`192.168.*` / `10.*` / `172.16.*`）
- `ARCHIVE` — 不该上传的备份/归档目录体积与文件数

## 判据与话术

- 真实凭据为 0 + 拓扑/个人信息 > 0 ⇒ **不能整个目录直接推**，报告里给表：类型 / 文件数 / 例子
- 排除归档备份后体积通常降到 1/10 以下，一并报出来（用户据此判断要不要拆仓）
- 报告要给出**三个可执行选项**（脱敏后公开 / 私有库全量 / 不传），不要只说「建议脱敏」

## 坑

- **只扫 `.md` 会漏**：凭据常在 `.py` / `.sh` / `.json`（脚本里的 key、备份里的 cron 配置）。按后缀白名单扫。
- **测试夹具里的假 key 会淹没结果**：`sk-abc...2345` 这类是刻意的脱敏占位。**必须先过滤占位再计数**，
  否则会向用户误报「发现 N 个密钥」。
- **私网 IP 在技能文档里是「教程内容」不是「配置」**：一个 networking 技能满篇 `192.168.99.X` 是正常的，
  真正要标的是**用户自己那台机器的实际地址**。区分办法：出现在代码示例/占位里的忽略，
  出现在 `references/` 正文里且对应用户设备清单的要报。
- **`$HOME/` 家目录路径本身不敏感**，但会和 IP、手机号一起构成可关联的身份指纹，
  报风险时要和 PII/TOPOLOGY 归为一类，不要单列成「安全问题」。
- **不要在报告里回显密钥原文**。只报 `文件:行号` + 类型 + 长度 + 前后各 4 字符掩码。

## 写脱敏器而不是手改：词边界是双向失效的

改 100+ 文件是破坏性操作（铁律 4），所以要**写脚本生成公开副本**，不碰原库。
但脱敏脚本本身有一个反复出现的失效模式：**同一条规则会同时“漏”和“误伤”，而两个方向都静默。**

### 边界太紧 → 漏

- **Python 的 `\b` 把中日韩字符也算 `\w`。** 所以「家目录路径」后面直接跟汉字时
  （`…/home/x目录整洁`）`\b` **不触发**，私人路径整条漏过去，且没有任何报错。
  用 `(?<![A-Za-z0-9_])` / `(?![A-Za-z0-9_])` 替代。
- **形态唯一的长标识不要加左边界。** 32 位大写十六进制的平台 ID 不会撞车；
  而泄露点恰恰常常在**扫描器自己的正则里**（`re.compile(r"\b<ID>")`），
  左边紧邻的 `b` 属于 `\w`，左边界会“正确地”拒绝匹配——整条漏出去。
- **私网段要覆盖 `.0` 结尾**（`172.31.99.X/16` 这种网段写法）与全 255 段。

### 边界太松 → 误伤/伤到内容

- `\b\d{8,}\b` 把 8 位**纯数字**（端口、日期）当 hash 抹掉。hash 必须要求含字母：
  `(?=[0-9a-f]*[a-f])[0-9a-f]{8,}`。

### 最隐蔽的一类：**脱敏产出的文件自己带私货**

脱敏脚本额外生成的东西（报告、统计、清单）通常**不在脱敏范围内**，
于是**它一边记录别人脱敏了什么，一边把原值抄下来**：

- 统计字典的 key 如果用**正则原文**当名字，报告就等于把被脱敏的字面量原样吐出。
  **规则名必须用中性名**（`VAULT_NAME_1`，不能写 `VAULT_VAULT`）。
- 文件名样本列表同理带原值——报告的价值是“动了多少处”，不需要带原文。
- **手写的 README/说明文档也会泄露**：写“家目录 `/home/xxx` → `$HOME`”时，
  表格里那个**示例本身就是原文**。用“（本机用户名）”这类描述代替。

**规则：脱敏范围必须包含「描述这次脱敏的产物」。**

### 验收：13 类模式复扫，残留必须 0

生成之后、推送之前，**独立于脱敏脚本**再扫一遍（用 grep 逐条计数，别信脚本自报）：

```bash
cd <公开副本>
for p in "192\.168\.[0-9]+\." "172\.16\.[0-9]+\.[0-9]+" "10\.[0-9]+\.[0-9]+\.[0-9]+" \
         "<平台id>" "<QQ号>" "/home/<用户名>" "<主机名>" "<Win机器名>" \
         "<私有vault名>" "<已知手机号>"; do
  n=$(grep -rEoh "$p" . 2>/dev/null | grep -v "^\./\.git/" | wc -l)
  [ "$n" != 0 ] && echo "残留 $p=$n"
done
```

⚠️ **扫描范围要含你新加的文件**（README / .gitignore 自己也会带私货），别只扫技能目录。
⚠️ **逐条定位到 `文件:行号` 再定性**——`grep -c` 命中的是**行数**不是**处数**，
且代码里的示例（讲怎么匹配某个模式）常是合理的命中。
