# 决策循环 · 九步

**触发**：任何非平凡任务的行动前——派活、写代码、调研、评估、配置、调试。

本技能是**统一入口**，不是又一份纪律。所有其他 skill 都是本循环在某领域的**参数**。

> 优先级：**本循环 > Ponytail > coding-delegation > MEMORY/USER**。
> `[待]` 条目保护**优先于**元规则「当场更正」。

完整版在 `~/.hermes/AGENTS.md`（启动时加载）。本技能补的是**各领域参数**。

## 循环本体

```
OBSERVE ──► ANALYZE ──► JUDGE ──► ACT
   ▲                                    │
   └──────── 失败：先找根因，再改规则 ─────┘
```

| 步 | 做什么 | 判据 |
|---|---|---|
| O1 可信度 | 实测输出 › 正式文件/源码 › 记忆 | 记忆只能生成假设，不能当判据 |
| O2 敌友 | 这条信息在帮我还是在干扰 | 干扰＝过期/无关/冲突/臆测 |
| A4 路由 | Research/Coding/Design/Doc | 加载对应 skill，**不加载不相关的** |
| A5 优先级 | 目标 › 事实 › 约束 › 资料 › 经验 | 上三层压过下三层 |
| A6 复用 | 这东西是不是已经有了 | 找现成工具/脚本/skill/stdlib/原生 |
| J 三问 | 查过没？冲突没？做过没？ | 任一答不上→ **停**，不推进 |
| A7 预测 | 先写预测再执行 | 涉及判断时必须先落纸 |
| A8 验证 | 跑真命令 | **工具输出 ≠ 我的结论** |
| A9 完成 | 交了≠能用了 | 必须一次真实往返 |

## 各领域参数

### Research 调研
先查本机已有（vault `VAULT/`、`INDEX.md`、历史会话），再补外部搜索。
**外部资料优先级低于本机现状**——本机目录才是权威。
→ `execution-discipline` · `enhanced-web-search`

### Coding 写代码
- **谁写**：`coding-delegation` 步 0 判定表（<50 行纯标准库可自己做；任何 .py/.sh/.yaml/系统配置派 Pi/Codex）
- **写多少**：Ponytail 阶梯——YAGNI → 复用现有 → stdlib → 平台原生 → 已装依赖 → 一行 → 才自己写
- **任务书**：八要素（目标/输入/输出/约束/禁改/验证命令/验收/原始需求）
- **prompt 卫生**：纯 ASCII、绝对路径、`IP:端口` 后不加句点
- **验收**：生产者不得自审；子 agent 产出走 `verifying-delivered-artifacts`

### Design / 配置
先看规范与现有资产（`network-management-system`、`system-health-check` 等），不凭空设计。
配置改动：**能改配置就不改代码**；改完必须验证生效（改文件 ≠ 进程读到）。

### Documentation 写文档
先核实事实再组织内容。**细节进 vault（`YYYY-MM-DD-工作复盘.md`），不堆 MEMORY。**
→ `obsidian-markdown` · `knowledge-vault-ops`

### 验收任何产出
1. 找到**可执行的验证命令**（不是"看起来对"）
2. 跑它，把**原始输出**贴出来
3. 输出与我的结论冲突 → **以输出为准**，重写结论
4. 对方是子 agent / 另一个模型 → 走 `verifying-delivered-artifacts`

## 三个真实失效模式

| 失效 | 症状 | 对策 |
|---|---|---|
| **沉默失败** | 日志全绿、功能是坏的 | A9：真实往返，不看日志下结论 |
| **纪律分散** | 同一纪律 5 处写、只命中 1 处 | 统一走 A7-A9，不靠单条 skill |
| **规则堆积** | 犯错就补一条→1000 行注意事项 | 写成**条件机制**，不是"下次注意" |

## 条件规则的正确写法

❌ 「上次出了这个问题，下次注意别再犯」（无触发条件、无判据）
✅ 「遇到 X → 先查 Y；若 Y 为真则做 Z；若 Y 无法确认则**先调查再决定**」

## 何时跳过本循环

纯闲聊、单文件读取/查询、可逆且已给明确指令的简单操作。
**不可逆操作一律不跳过**（且执行前找浩哥确认一次）。
