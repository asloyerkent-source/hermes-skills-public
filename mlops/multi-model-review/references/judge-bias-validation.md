# 判官偏差的受控实测（怎么验「偏差图谱」是真的）

SKILL.md 里那张「判官四种系统性偏差」表是**主张**，不是已验证事实。
要把它落成证据，必须用受控设计；**拿真实输出的相关性去事后凑，测不出结论。**

## 为什么要受控：事后相关性的反例

拿同批多模型审核输出，量「输出长度 vs 好评倾向」的相关性：

```
数据集甲   r = -0.713   （越长越负面）
数据集乙   r = +0.996   （越长越正面）
```

**同一类数据、同一套测法，结论完全相反** —— 这就是判官「没有测出任何东西」。
两个成因叠加：情感倾向用了粗糙的正负词计数当代理（代理本身没被验证过），
n=4 且有个离群值单独把 r 拉到 0.996。

> **铁律：一个检查器在同一类数据上给出自相矛盾的读数，说明它没有分辨力。不要汇报它的输出。**
> 报一个自己都不信的 r 值，比不报更糟 —— 它会被当成证据用下去。

配套信号：**测长度偏差时，拿「真实输出长短」当自变量是不成立的** ——
长度与内容、模型、任务难度全都混淆在一起。必须人为控制长度这一个变量。

## 受控设计（成对比较 + 位置互换 + 两档注水强度）

**材料**：同一份技术解释做两版，**事实信息完全相同**，只改铺陈量。

| 版本 | 做法 |
|---|---|
| 精简 | 直给结论 + 机制 + 修法，无过渡句 |
| 注水·明显 | 免责声明、口头禅（「首先我们要明确一点」）、整段重复、泛泛背景 |
| 注水·隐蔽 | **专业语气、零废话**，但加背景段、复述机制、追加总结段 —— 字数翻倍，信息量不变 |

**两档强度是这套设计的核心。** 只有「明显」档时，判官靠「一看就是废话」就能蒙对，
测不出真正的长度偏差。隐蔽档才逼它判断「这些额外铺陈算不算冗余」。

**矩阵**：每模型 × 每强度 × 2 轮顺序

```
轮1：A=精简  B=注水
轮2：A=注水  B=精简     ← 必须互换，否则位置偏差与内容偏好分不开
```

**提问模板**：先给判断标准（信息是否准确/完整、是否有冗余），再**明说「两版事实信息相同，只差行文长短与铺陈」**，
要求只回 `<字母>|<一句话理由>`。强制短输出，便于正则解析。

## 读数与判读

| 指标 | 算法 | 无偏差时应为 |
|---|---|---|
| 长度偏差 | 注水版被选中轮数 / 有效轮数 | **显著 < 50%**（内容相同，精简更优） |
| 位置偏差 | 选「A」的轮数 / 有效轮数 | ≈ 50% |

**关键对照——按强度分组看，不要只看总胜率：**

- 隐蔽档注水胜率 **明显高于** 明显档 → 判官**只在废话明显时才识别冗余**，这本身就是长度偏差的间接证据。
- 两档都 < 50% → 这批判官对长度不敏感，**偏差表在此条件下不成立**（照实报「未复现」，不要回护表里的说法）。

**把每个模型的选择映射回内容再统计**（`A is concise ? A : padded`）——
直接统计字母会把位置偏差混进内容偏好里。同时把各轮理由原样存下来：
理由是判「跟着内容走还是跟着位置走」的直接证据。

**样本量**：≥4 模型 × 2 强度 × 2 轮 = 16 格。少于这个量级，任何胜率都只是噪声。

## 跑之前的坑

- **provider 的 RPM 上限会让批量调用中途报错，看起来像「模型名不兼容」。**
  实测：同一模型单条手工调用 200，脚本里连发就报 400；真实原因写在**响应体**里
  （`request reached organization max RPM: N`）。**4xx 先读 error body，再怀疑模型名。**
  批量脚本必须带**指数退避重试 + 每次调用间固定 sleep**。
- **慢模型要把单次超时放大。** 默认 120s 会让慢模型在矩阵里整格缺失；提到 180s。
- **别给要求 `temperature=1` 的 provider 传 `temperature: 0`** —— 那会直接 400，
  与偏差结论无关，却会被读成「这个模型不可用」。
- **失败格子记 `None` 并单独列出**，不要从分母里悄悄抹掉 —— 缺失与「选了对方」是两回事。

## 记录格式

落盘 JSON：`[{model, cells:[{variant, rnd, letter, chosen, raw}]}]`，`chosen` 是映射回内容的结论不是字母。
汇报时给**矩阵本身**（每模型每格选了什么）+ 分组胜率，不要只给一个总百分比。
