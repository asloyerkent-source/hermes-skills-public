# 私有数据出网守卫 (Private Data Egress Guard)

## 触发
- 你要写/跑脚本把用户文件/聊天/笔记发给云端 LLM（LongCat/Mem0/Honcho 等）做提炼、摘要、分类、向量化、记忆写入
- 用户知识库/聊天记录要"批量喂"给记忆 provider 或模型
- 涉及 `hermes memory setup` / Holographic / Mem0 / 任何外部记忆或摘要服务
- 准备把"背景知识/资料/文档"喂给模型增强能力

## 边界：搜公开资料 ≠ 私料出网（2026-10-03 用户澄清）

用户原话：「不上网是指我填了的个人隐私资料，目前没有本地模型，基本上还是要网上模型处理分析的」

| 行为 | 允许？ | 理由 |
|---|---|---|
| `web_search` / `web_extract` 查公开资料（行业标准、法规、健康知识） | ✅ **不用问** | 查出去的是查询词，不是用户私料 |
| 为做问卷/报告去搜行业标准、参考案例 | ✅ **不用问** | 同上 |
| 把用户填的问卷原文、档案、存款/收入/病史**发给云端模型处理** | ❌ **必须先确认** | 这才是「出网」 |
| 把私料喂 LongCat/Mem0/Honcho 做提炼 | ❌ **必须先确认** | 见下 |

**判据一句话**：`web_search("应急金标准")` 不出网；`web_search` 里塞进用户的存款金额，或把档案整篇发给模型提炼，出网。

**注意**：本机没有本地模型，**任何分析都必须走云端** —— 所以私料一旦交给子代理/多模型审稿，就是出网。
派活前先判断资料里有没有私料，有就先问浩哥。

## 铁律（2026-08-25 翻车后定）
**含私有数据 → 先给用户确认，不得无人值守批量喂。**

用户原话："银行账户，地址等已经上云了，没办法，但应该给我确认过的"——敏感私料出网前必须过用户目，事后补救不如事前确认。

## 为什么容易踩（关键认知）
**本地存储 ≠ 不出网。** 即使记忆 provider 标 `local-first` / 纯本地 SQLite（如 Hermes Holographic），**提炼那一步调的是云端模型（LongCat/Mem0/Honcho）也会出网一次**。
- 错误以为："Holographic 是本地 SQLite，所以喂它安全" → 错。喂之前要先 `add_fact`/`extract_facts`，若提取用云端 LLM，原文已出网。
- 正确做法：批量喂前先**筛敏感词**（王浩/身份证/支付宝/地址/银行卡/手机/健康/家人），或先问用户"这批含私料吗？要确认吗？"

## 执行步骤（批量喂私有资料前）
1. **识别数据源属性**：公共知识（AI论文/技术文档）还是私料（微信聊天导出/订单/联系人/家庭/健康/红线类）？
2. **扫敏感词**：用**形态**正则，不要把真实值当关键词写进脚本/文档：
   - 身份证 `(?<!\d)\d{17}[\dXx](?!\d)`
   - 手机 `(?<!\d)1[3-9]\d{9}(?!\d)`
   - 卡号/支付账户 `(支付宝|收款|银行卡|账号)[：:=\s]*\d{6,20}`、`(?<!\d)\d{16,19}(?!\d)`
   - 住址 `[\u4e00-\u9fa5]{2,8}(省|市|区|县)[\u4e00-\u9fa5]{2,10}(路|街|道|巷)\d{1,5}号`
   - 邮箱 `[\w.+-]+@[\w-]+\.[\w.]{2,}`
   - 健康/家人等语义词（这类没固定形态，只能列表）

   ⚠️ **写扫描规则时不准出现真实值**。本技能历史版本把用户小区名/门牌号直接写进正则，
   那等于把住址写进了一个要被提交、被同步、可能被公开的文档（2026-09-30 事故）。
3. **含私料 → 停，给用户看清单**：导出命中样本（如 `王浩相关事实_待确认.md`），列"有哪些敏感信息"，等用户拍板（留/删/隔离/全不喂）。
4. **用户授权后才喂**，记录"已确认出网"事实。
5. **喂后复盘**：若已进本地记忆，按用户指令筛删（见 references/pii-cleanup-case-2026-08.md）。

## 红线对照（用户既定）
- `perm_noredline`：不接外部 Agent 网络 / 不同步云端第三方
- `perm_wanghao` / `perm_gene` / `perm_health`：王浩纪念照片/基因/体检硬隔离不上云
- 扩展理解：王浩的**身份证号/住址/支付宝/行踪/健康**敏感度不低于照片，同样须隔离；聊天记录里的此类信息被云端提炼即出网，须事前确认。

## 2026-09-30 事故：写守卫的技能自己泄了真料

把技能库推上 GitHub 公开库，2 小时 48 分钟后才发现里面有：
用户**身份证号** + **家庭住址** + **支付宝账户**，散在 6 个文件里。已删库（未被爬虫索引）。

**三个层次的失败，性质完全不同**：

| 层次 | 发生了什么 | 为什么自测抓不到 |
|---|---|---|
| 规则层 | 脱敏规则表里**压根没有**「身份证/支付账户/住址/邮箱」这一类 | 按「我以为有什么」列规则，没按「泄露后果有多重」列 |
| 文档层 | 本技能的敏感词清单里**写着用户的真实住址片段** | 写规则时没意识到这个文件本身就是要被提交的 |
| 认知层 | 在写「防私料外泄」的技能，同时在**另一个**技能里贴真身份证当脱敏示例 | 防护意识没有跨文件生效 |

**两条要记住的**：
1. **脱敏规则要按泄露后果排，不是按你记得的排。** 身份证/住址/支付账户后果都比手机号重，
   而第一版只想到手机号、IP、路径。后果越重的越要先设。
2. **写「防泄露」的东西时，先自问：这份文档自己会不会被公开？** 本技能当时没有 git，
   后来纳管了——**纳管那一刻才是真边界**，之前的「文件在本地」是安全的假设，不是保证。

## 陷阱（Pitfalls）
- **守卫自己不做守卫**：凡是「防私料外泄」的技能/脚本/文档，先拿扫自己的真料扫一遍。
  本技能旧版把住址片段写进敏感词清单，成了泄露点本身。
- **无差别批量喂**：`find VAULT -name '*.md' | xargs 提炼` 会把微信聊天记录全送云端。先分类再喂。
- **以为 local-first 不出网**：提炼步是出网点，本地 SQLite 只是存储端。
- **事后才发现**：用户问"到底干了啥"才暴露。批量操作前先小样确认（抽100条给用户看）比事后清干净。
- **删除不能挽回出网**：从本地 holographic 删掉事实，但云端那次提取已不可逆。事前确认 >> 事后清理。
- **云端LLM主语错乱（提炼质量坑）**：聊天记录喂 LongCat 等云端模型提炼时，它会**搞错主语**——本例把"我(用户)12-21混阳、12-23退烧咳嗽"误归成"王浩感染新冠"。根源：上下文里王浩被@多次，模型张冠李戴。**对策**：凡从聊天记录提炼出涉及健康/PII/行踪的事实，必须回原文件核对主语（"我" vs 具名人物），不能轻信提炼结果。提炼"王浩新冠"这类事实前，先读 src 原文确认患者是谁。
- **自动相似度去重会删掉真实事件（整理坑）**：全息库3.6万事实想"合并近似重复"，用"前N字相同聚类"会把**不同合同号/不同金额/不同日期**的聊天流水当重复删（如"5月20日发图"vs"11月20日发图"、合同AA15024002 vs AA09624065）。这些结构相似但**实体不同=不同事件**，合并即丢数据。**安全做法**：只做"去标点+去空白+小写后完全等价"的合并（仅差标点/大小写，实体100%一致），约几十~几百条，零误删。语义级合并在聊天流水数据上不可靠，放弃。详见 `references/holographic-fact-dedup.md`。
