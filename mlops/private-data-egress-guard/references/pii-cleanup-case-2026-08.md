# PII 清理真实案例 (2026-08-25, 【当事人】事实)

## 背景
VAULT 微信聊天记录被无差别批量喂 LongCat 提炼，写进本地 Holographic（~36500 条事实）。
用户复查发现含【当事人】敏感私料，要求清理。全息库 `src:2022-12.md` 等聊天导出是来源。

## 全息库事实位置
- db: `~/.hermes/memory_store.db`（本地 SQLite，Hermes Holographic）
- 查【当事人】: `select fact_id,content,category from facts where content like '%【当事人】%'`
- tags 含 `src:<文件名>` 可追溯来源

## 【当事人】事实规模
- 总数 226 条（含"【当事人】"二字）
- 分类: 身份证1 / 支付宝2 / 手机~100+ / 住址~80 / 家人4 / 健康2 / 行踪~6 / 公司~31 / 样品收发~70 / 其他

## 用户最终指令（逐条执行）
1. **身份证/地址/手机/支付宝 4类每留1条，其余删**
2. **家人4条全删**
3. **公司/职务类有重复 → 整理合并**（留合并后，不简单删）
4. **样品收发类：配到对方地址/电话/公司抬头的留，配不到的删**
5. 健康/行踪类未提 → 先不动，等健康时间线挖完再定

## 执行技术点
- 判定"4类敏感"正则: `\d{17}[\dXx]`(身份证) / `支付宝|银行卡|账户` / `<PHONE>|电话` / `<小区名>|门牌号|地址|<区县名>`  ← 语义类无固定形态，靠枚举，
  但**枚举的必须是占位符，不是真名**（本行旧版直接写了用户真实小区名，2026-09-30 事故）
- "配到对方信息"判定: 含 `<供应商名>|地址|电话|<PHONE>|顺丰|SF|京东|收件|发货|开票|到付|<地址片段>|订单|xls` 等 → 留；否则删
- **删前先备份**: `json.dump` 已删事实到 `~/HermesShare/【当事人】已删事实_备份.json`（防反悔，但备份本身也是敏感文件，勿同步云）
- 删除: `delete from facts where fact_id=?`

## 保留的4条样本
- 身份证: `【当事人】身份证号<ID_CARD>` (fid=21753)
- 支付宝: `收款支付宝<ACCOUNT>户名【当事人】` (fid=6744)
- 手机: `收件人【当事人】电话<PHONE>` (fid=4187)
- 地址: `7月14日收货地址<ADDRESS>【当事人】<PHONE>` (fid=1878)

## 关键教训
- 云端出网不可逆：删本地 holo 救不回 LongCat 那次提取
- 分类脚本的"其他杂项"易误删：先保守（只动明确指令的3类），未明说的先列给用户看
- 用户"其他63条"实际是104条（分类口径差），实查为准
