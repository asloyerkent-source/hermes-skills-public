# 场景专属要求与篇幅档位（逐字抄自内核）
> 常量 `SCENARIOS` / `STRENGTHS`。场景决定追加哪些额外要求，档位决定篇幅密度。

> **2026-09-27 筛选：原 8 个通用场景已按用户实际工作裁到 4 个。**
>
> | 现役（下文有全文） | 已弃用（原文见 `deprecated-scenarios.md`） |
> |---|---|
> | 编程开发、文档写作、数据/表格处理、图像生成 | 通用 Agent、学术科研、数据分析、视频脚本 |
>
> 裁刃依据：四模型独立审 + 用户档案（宁波外贸，产品全生命周期）。

## 场景：编程开发
```text
本场景额外要求（软件开发/代码任务）：
- 明确技术栈与版本、目录/文件路径、需要改动的具体文件；
- 写明运行与验证方式（构建/测试命令、期望输出）；
- 列出禁止改动范围与兼容性约束（不改公共 API、不引入新依赖等）；
- 要求给出可回滚的改动边界与自检清单。
```

## 场景：文档写作
```text
本场景额外要求（文档/写作任务）：
- 明确读者画像、文体（正式/科普/公文）、篇幅区间与章节结构；
- 规定术语统一口径与禁用表达（避免绝对化、避免营销腔）；
- 要求事实与观点分离，数据必须标注来源或占位待补；
- 给出可直接使用的标题层级与段落组织方式。
```

## 场景：图像生成
```text
本场景额外要求（图像 / 3D 模型 / 视觉创作任务）：
- 按 A 类策略输出自然描述，不要开需求模板；
- 描述中自然覆盖：主体与特征、比例或构图、材质或质感、配色、光线或氛围、输出内容（视图 / 角度 / 件数）；
- 目标平台是 Stable Diffusion / ComfyUI 等时，段末补一行「避免出现：…」（Negative prompt）。
```

## 场景：数据/表格处理
```text
本场景额外要求（表格处理任务）：
- 明确输入文件路径与表结构（表头、行数、编码）；
- 明确处理规则与优先级、冲突时的取舍；
- 明确输出文件路径、格式与校验方式（行数守恒、字段完整性）。
```

## 篇幅档位

### 精简

```text
篇幅与密度：改写保持紧凑。A 类输出一段话（约原文的 2~4 倍）；B 类只保留目标、关键约束与输出格式（不超过原文的 2 倍）。
```

### 标准

```text
篇幅与密度：A 类完整展开创作维度（约原文的 3~8 倍）；B 类轻结构化（约原文的 1.5~3 倍）。
```

### 详尽

```text
篇幅与密度：A 类可在描述之后追加简短的「规格清单」（尺寸 / 视角 / 输出件数等）；B 类可含异常处理与验收要点。两种类型都仍禁止注水与八股模板。
```
