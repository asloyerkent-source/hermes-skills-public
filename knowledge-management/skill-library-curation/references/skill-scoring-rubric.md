# 技能评分：九维加权 + weighted_gap

来源：darwin.skill 2.0（`alchaincyf/darwin-skill`，MIT）的评分框架，借鉴 Karpathy autoresearch
的实验循环（program.md / train.py / val / git ratchet）。本机已有的同源机制见铁律 2（独立验证）、
铁律 17/21（评分器读数通道自验）—— 本文只补那几条没有的部分。

## 一条关键的外部依据

**LLM 自我评估准确率只有 46.4%**（SkillLens 论文的实测）。这条把铁律「生产者不得自审」
从实践偏好升级成有量化支撑的硬约束：**自己改自己打分等于抛硬币**。

## 九维评分（满分 100）

结构分（静态分析）+ 效果分（实跑测试）。v2.0 的三个新维度来自 SkillLens 的实证 rubric：

| 维度 | 判什么 | 本机对应物 |
|---|---|---|
| 结构合规 | frontmatter/路径/指针 | `scripts/skill_repo_doctor.py` |
| **失败机制编码** | 显式编码已知失败路径，不是「小心点」 | 铁律 18/29/31 |
| **可执行具体性** | 禁模糊词 | 见下方禁用词表 |
| **高危动作黑名单** | 不可逆操作必须显式禁 | `flows/approval-gate` |
| **实跑效果**（权重最高） | 真跑一遍看产物 | 铁律 9 |
| 其余五维 | 触发、边界、导航、去重… | 铁律 20/32/33 |

**效果分权重最高** —— 一份写得漂亮但跑不出正确产物的技能仍然是坏技能。
本机现状：多数技能只做了结构体检，**不测实跑效果**，这是评分体系里最大的缺口。

## weighted_gap：防止低权重维度刷分

```
weighted_gap = weight × (10 − score) / 10
```

取 weighted_gap 最大的那个维度作为本轮唯一优化目标（一轮只改一个维度）。
**机制：低权重维度即使从 0 提到 10，weighted_gap 上限也只有 weight，
而高权重维度差 1 分就贡献 10×weight/10 = weight** ——
所以「刷简单维度」在算式上永远不划算。

**判据：本技能现有的任何「优先改 X」的排序，如果只是拍脑袋定序，
就等于允许通过刷简单项假装进步。** 排序要有公式，否则它只是偏好不是门禁。

## 可执行的具体性：禁用模糊词

写技能正文时这几类词出现即扣分，因为它们把判断推回给模型而技能本身没提供信息：

`suggest` / `could consider` / `depending on` / `use judgment` / `case by case`
/「建议」「可以考虑」「视情况」「酌情」「大概」「应该可以」

**判据：一句规则里去掉所有模糊词后，如果它变成了「做 X」而不是「根据情况做 X 或 Y」，
说明那句规则本来就不该存在。**

## 早停与反注水

- **单轮涨幅 < 1 分 → 自动停**。连续多轮只涨零点几分就是在为刷分改措辞，不是真改进。
- **多轮只改措辞不改判据** = 指纹（对照铁律 20：description 反复改措辞却总改不动）。
- **dry-run 比例 > 30% → 报警**。大量「改了但没验证」的轮次说明循环在空转。

## 独立评审的三条纪律

1. **每轮新开 judge，绝不复用** —— 复用的 judge 会被上一轮的锚定影响。
2. **一次只改一个维度** —— 同时改多处无法归因，涨了不知道是谁的功劳。
3. **回滚用 `git revert` 不用 `git reset --hard`** —— 后者会丢掉本轮实验前的现场，
   出事时无法对比。

## 人工确认点

darwin 在三个阶段强制暂停等人确认：基线评估报告、单维度编辑前、回归测试后。
**判据：技能质量比训练损失更主观，全自动循环容易把「分数涨了」当成「技能变好了」。
凡本技能要引入自动化评分循环，这三个检查点不能省。**
